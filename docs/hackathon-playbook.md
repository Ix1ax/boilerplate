# Playbook на 48 часов

Критерии прошлого хакатона (Столото, «Помогать проСТО») — шаблон оценки следующего: жюри проверяет **сквозные сценарии ролей**, а не инфраструктуру. Ниже — как шаблон закрывает критерии и что делать по часам.

## Что оценивают (по вкладу в баллы)

| Блок                      | Баллы | Что проверяют                                                                                                                                         | Что даёт шаблон                                                                              |
| ------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Продукт и процессы        | ~50   | Контуры ролей (волонтёр, фонд, админ), сквозная логика, доп. возможности: лендинг, мотивация, уведомления                                             | Каркас ролей `user`/`admin`, модерация (`copilot`), события через RabbitMQ — домен пишете вы |
| Готовность сценариев + UX | ~60   | 10 сценариев работают и выглядят хорошо, адаптивность, доступность, понятные статусы                                                                  | Base UI, формы, страницы-образцы; **статусы и пустые состояния делайте на каждом экране**    |
| Архитектура               | ~25   | Backend и модель данных, масштабируемость, интеграция (корпоративная почта/ID, мок-база сотрудников, выгрузки), **только свободное ПО (0 или 10)**    | Микросервисы, БД на сервис, outbox/RabbitMQ; лицензии проверены                              |
| Код и документация        | ~18   | Структура, непустой `.gitignore`, комментарии по-русски, README со стеком, запуском, сценариями и тестовыми пользователями, health-check, **Swagger** | `make demo` печатает пользователей, Swagger на `/api/docs`, `/healthz`, `/readyz`            |
| Презентация и выступление | ~15   | Читаемость слайдов, живая демонстрация ролей                                                                                                          | `docs/jury.md`, сценарий демо на 3 минуты                                                    |

Ключевое: **один непрерывный путь** через все роли (создал → прошёл модерацию → откликнулись → подтвердили → начислили → попало в отчёт) стоит больше десяти разрозненных функций. «Если сценарий не реализован, оценивается дизайн-прототип» — недоделанное всё равно показывайте экранами.

## Что НЕЛЬЗЯ потерять (быстрые баллы)

- [ ] README: стек, структура, запуск (`make demo`), сценарии, тестовые пользователи для **каждой роли**.
- [ ] Swagger покрывает основные сценарии: после изменения API `make docs-sync` и `npm run gen -w @starter/contracts`.
- [ ] Выгрузка отчёта в CSV из админки (участники, отклики, выполненное, часы, категории) — образец `apps/tasks/internal/tasks/export.go`.
- [ ] Возврат на доработку с комментарием и история статусов — `Workflow.RequireComment` + `RecordTransition`.
- [ ] Документы к заявке — вложения в `files` (`entity_type`, `entity_id`).
- [ ] Реалистичные демо-данные — `fixtures/*.json` + `make seed`.
- [ ] Бот MAX для уведомлений: токен получить **до хакатона** (верификация организации и модерация бота), затем `MAX_BOT_TOKEN`/`MAX_BOT_USERNAME` в `.env`.
- [ ] Уведомления на ключевых шагах сценария — событие `notification.requested` через outbox, колокольчик уже в шапке.
- [ ] Регистрация по корпоративной почте/ID с замоканной базой сотрудников (seed-таблица + проверка при регистрации).
- [ ] Только свободное ПО: ничего платного и с несвободной лицензией (проверяйте новые образы и модели!).
- [ ] Комментарии на русском, непустой `.gitignore`, нет секретов в git.

## План по часам

| Часы      | Что делаем                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| До старта | `make prefetch` на хорошем интернете у каждого участника: на площадке сеть может не вытянуть гигабайты образов и модель.                       |
| 0–2       | Разбор ТЗ и критериев, названия сущностей и статусов, схема ролей, раздача задач. `make demo` у всех работает.                                 |
| 2–6       | Модель данных и миграции, новые сервисы по рецепту из `AGENTS.md`, контракты в OpenAPI. Параллельно: дизайн-токены, лендинг.                   |
| 6–20      | Сквозной путь ролей: бэкенд и фронтенд по одному сценарию за раз, сразу с seed-данными и e2e.                                                  |
| 20–32     | Админка, отчёты и экспорт, уведомления (события RabbitMQ → таблица уведомлений → колокольчик в UI).                                            |
| 32–40     | Дополнительное: мотивация (бейджи, прогресс), ИИ-функция с человеком в контуре, аналитика.                                                     |
| 40–44     | **Заморозка функций.** Тесты, `make check`, исправление багов, адаптивность, пустые/ошибочные состояния.                                       |
| 44–48     | `make loadtest` → цифры в слайд, `make slides` из `docs/presentation.md`, репетиция демо, запасное видео, `make reset` перед выходом на сцену. |

## Правила, которые экономят часы

1. Один сценарий — один вертикальный срез (миграция → сервис → контракт → UI → seed → e2e). Не копите «горизонтальные» заготовки.
2. Не добавляйте сервис, если хватает модуля внутри существующего. Границы сервисов — по независимым данным, не по числу людей.
3. Статусные машины (черновик → на модерации → опубликовано / возврат с комментарием) пишите явными перечислениями и проверяйте переходы в одном месте.
4. ИИ — как помощник модератора (см. `apps/tasks/internal/copilot`): правила решают, модель советует, человек подтверждает. Используйте только модели со свободной лицензией (Qwen2.5 1.5B/7B — Apache 2.0; 3B — нет).
5. Демо должно работать **без** модели: все ИИ-функции деградируют до правил.
