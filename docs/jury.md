## 4. Архитектура

- Схема: браузер → Nginx → gateway → сервисы (tasks, files, llm, …) → Postgres (база на сервис), Redis, S3, Ollama. Подробности — `docs/architecture.md`.
- Что подчеркнуть: единая точка входа, проверка прав и владельца в Go и SQL, независимые сервисы и базы, локальная LLM без внешних платных API (данные не покидают контур).

## 5. Безопасность и качество

- Keycloak OIDC + PKCE, HttpOnly-сессии, CSRF по Origin, rate limit (60 изменений/мин; 10 запросов/мин к LLM).
- Тесты: `make check`, `make integration`, `make smoke`; CI на каждый pull request.
- Ограничения LLM: валидация входа и выхода, лимит параллелизма, человек в контуре.

## 7. Риски и дальнейшие шаги

## 8. Вопросы жюри (заготовки ответов)

- Почему микросервисы для MVP? Границы доменов, независимый деплой и база на сервис; цена — больше инфраструктуры, поэтому шаблон автоматизирует её.
- Что если модель ошибётся? Результат проверяется схемой/правилами, решение принимает человек, факты берутся из БД.
- Как масштабировать? Сервисы stateless; Redis общий для лимитов и сессий; Ollama заменяется адаптером на другой провайдер.
