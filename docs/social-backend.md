# Социальные возможности API

Связь с кейсом: обсуждение и ответ организатора — обязательный сценарий 5;
друзья, личные сообщения, отзывы, истории и клубы — дополнительные возможности.
Все запросы идут через gateway с обычной сессией. Изменяющие запросы требуют CSRF;
для безопасного повтора используйте `Idempotency-Key`.

## Друзья и личная переписка

| Действие | Маршрут |
|---|---|
| Друзья и заявки | `GET /api/v1/my/friends` |
| Отправить заявку | `POST /api/v1/friends/{user_id}/request` |
| Принять / отклонить входящую | `POST /api/v1/friends/{user_id}/accept`, `/decline` |
| Удалить друга / отозвать исходящую | `POST /api/v1/friends/{user_id}/remove` |
| Открыть личный чат | `POST /api/v1/chats`, JSON `{"user_id":"..."}` |
| Свои чаты | `GET /api/v1/my/chats` |
| История / отправка сообщения | `GET /api/v1/chats/{id}/messages`, `POST` с `{"body":"..."}` |

Встречная заявка не принимает дружбу автоматически. На пару существует один чат.
Сообщения до 2000 символов сохраняются в PostgreSQL. Читать историю могут только
двое участников; администратор не получает доступа к личной переписке через эти API.
После удаления дружбы история остаётся у обоих, отправка новых сообщений запрещена.

В личный WebSocket-канал `user:<id>` приходят сигналы `friendship.changed` и
`chat.changed` с `id`. Тело переписки через сигнал не передаётся. После сигнала
клиент перечитывает авторизованный API. Изменение и сигнал записываются одной
транзакцией через outbox.

## Чат мероприятия

Чат существует автоматически для каждого мероприятия. Дополнительного запроса
создания нет. История, ответы организатора и модерация используют существующие
`GET/POST /api/v1/events/{id}/comments`.

`GET /my/chats` объединяет личные чаты и мероприятия организатора или подтверждённого
участника. Поле `kind` различает `direct` и `event`; `messages_url` указывает API
истории. Вторая копия комментариев не создаётся. Вопрос к открытому мероприятию
по-прежнему можно задать через comments до записи, согласно прежним правилам доступа.

## Отзывы

`POST /api/v1/events/{id}/reviews` принимает `score` от 1 до 5 и `body` до 2000
символов. Отзыв оставляет подтверждённый участник после окончания опубликованного
события. Если время окончания не указано, используется начало плюс два часа.
Организатор не оценивает собственное мероприятие; на автора и событие допускается
один отзыв, включая скрытый.

`GET /api/v1/profiles/{user_id}/reviews` выдаёт видимые отзывы мероприятий
организатора. Для снятых и отменённых событий отзывы не раскрываются.
`POST /api/v1/reviews/{id}/hide` с обязательной `reason` скрывает отзыв автора
или администратора. Организатор не может удалять чужую критику.

Запись на мероприятие не доказывает фактическое посещение. Отзывы не превращаются
в оценку надёжности или посещаемости участника.

## Истории и медиа

`POST /api/v1/stories` принимает текст `body` от 1 до 1000 символов. История живёт
24 часа с момента создания и видна автору и подтверждённым друзьям.
`GET /api/v1/stories` возвращает только доступные, живые, неудалённые истории.
После удаления дружбы доступ к историям бывшего друга пропадает сразу.

Медиа прикрепляется один раз: `POST /api/v1/stories/{id}/media`, multipart-поле
`file`. Разрешены JPEG, PNG, WebP, GIF, MP4 и WebM, тип определяется по содержимому,
размер от одного байта до 10 МиБ. Загрузить файл может только автор живой истории.
Внешние URL и идентификаторы файлов других сервисов не используются.

Бинарные данные хранятся в отдельном приватном S3-бакете events. Метаданные и права
принадлежат events. В API возвращается только `media_url` вида
`/api/v1/stories/{id}/media`. Этот GET повторно проверяет аудиторию и срок истории;
прямой адрес S3 не выдаётся. Ответы помечены `private, no-store`.

`POST /api/v1/stories/{id}/delete` с `reason` удаляет историю автора или
администратора. Доступ закрывается сразу. Фоновая `CleanupStoryMedia` физически
убирает объекты удалённых и истёкших историй, а также незавершённые загрузки старше
часа. При недоступности S3 очистка повторяется; неудачная загрузка не публикует ссылку.

## Клубы

Клуб использует существующую организацию: создать организацию уже можно было,
публикация от её имени разрешается после допуска администратором.

`POST /api/v1/organizations/{id}/membership` вступает в допущенный клуб;
`DELETE` по тому же адресу выходит. Повторные запросы не создают дубликатов.
`GET /api/v1/organizations/{id}/members` доступен владельцу клуба и администратору.
Членство не даёт права редактировать организацию или создавать события от её имени.
Владелец управляет клубом без отдельной записи членства.

## Страницы и ошибки

Новые списки принимают `limit` от 1 до 100 (по умолчанию 30) и непрозрачный `cursor`.
При наличии `next_cursor` передайте его следующему запросу. Порядок — от новых к
старым по времени создания и идентификатору. Курсор относится к конкретному списку;
его не нужно разбирать или изменять.

Некорректные поля дают 422; неизвестный или недоступный объект — 404; переход,
невозможный в текущем состоянии, — 409. Медиа дополнительно возвращает 413 для
превышения размера, 415 для недопустимого типа и 503 при недоступном S3.
