# Как устроен шаблон

## Путь запроса

Браузер работает с Next.js на одном origin. Маршрут `/api/[...path]` принимает только пути `/api/v1/*`, для записи проверяет `Origin`, читает HttpOnly cookies и вызывает Go API. Произвольный адрес upstream клиент задать не может.

Go проверяет JWT, назначает идентификатор запросу, ограничивает размер тела и выполняет обработчик. Для изменяющих запросов к предметным модулям Redis проверяет общий лимит. Репозиторий всегда добавляет `owner_id` к условию чтения, изменения или удаления.

## Авторизация

`/auth/login` создаёт случайные `state` и PKCE verifier. В Keycloak отправляется S256 challenge; verifier хранится в короткоживущем HttpOnly cookie. `/auth/callback` сверяет `state`, обменивает код и проверяет access token через Go API.

JWT проверяет `go-oidc`: подпись, публичный issuer, audience `hackathon-api` и срок действия. В Docker discovery и JWKS запрашиваются через внутренний адрес Keycloak. Значение issuer в самом токене при этом остаётся публичным.

Access и refresh token сохраняются в HttpOnly cookies с `SameSite=Lax`, путём `/api` и сроком жизни из ответа Keycloak. Внешний HTTPS требует `SESSION_COOKIE_SECURE=true`. В localStorage и sessionStorage токены не записываются.

BFF обновляет access token при его отсутствии или ответе 401, затем повторяет запрос один раз. Параллельные обновления одного refresh token в процессе Next.js объединяются. В локальном realm ротация refresh token выключена, поэтому несколько процессов не инвалидируют сессии друг друга. Если включаете ротацию или масштабируете приложение, сначала перенесите сессии и координацию обновления в общее хранилище.

Выход очищает cookies и открывает endpoint завершения сессии Keycloak. Он может показать подтверждение выхода: ID token в шаблоне не хранится. JWT, который уже был выдан, действует до своего `exp`; по умолчанию это пять минут.

## Пользователи и роли

Пользователи хранятся в Keycloak; отдельной таблицы пользователей в приложении пока нет. `sub` служит ключом владельца задач и файлов. При смене realm потребуется миграция владельцев или новая база.

Роли берутся из проверенного `realm_access.roles`. Для примера предусмотрены `user` и `admin`; демопользователи получают только `user`. Администратор Keycloak и роль администратора приложения — разные вещи. Для проверки `GET /api/v1/admin/ping` назначьте пользователю realm-роль `admin` в админке.

Проверка прав находится на сервере. Скрытая кнопка во фронтенде не ограничивает доступ к API.

## Данные и файлы

PostgreSQL хранит задачи и метаданные файлов, SeaweedFS предоставляет S3-совместимое хранилище. Имена объектов формируются из `sub` и UUID, исходное имя не используется как путь. Скачать файл можно через API, предъявив токен владельца.

При загрузке API проверяет фактический MIME-тип и размер. Допустимы PNG, JPEG, WebP, PDF и текст. Файлы выдаются как вложения с `nosniff`. Антивирусной проверки и фоновой обработки нет; если они нужны новому проекту, добавьте очередь и обработчик.

Если запись метаданных не удалась, API пытается удалить загруженный объект. При сетевом сбое возможны объекты без метаданных; для длительной эксплуатации нужна периодическая сверка хранилища с базой.

SQL-миграции встроены в бинарник `migrate` через `embed`. Контейнер миграций завершает работу до запуска API. Новые миграции добавляются отдельными файлами; применённые файлы не редактируются.

## Границы модулей

- `apps/api/internal/tasks`: пример разделения модели, сервиса, репозитория и HTTP-обработчиков.
- `apps/api/internal/platform`: подключения к инфраструктуре.
- `apps/web/src/screens`: композиция страниц.
- `apps/web/src/features`: формы и пользовательские действия.
- `apps/web/src/entities`: запросы предметной области.
- `packages/contracts`: общие TypeScript-типы и Zod-схемы, OpenAPI.
- `packages/ui`: компоненты без привязки к API и предметной области.

У небольшого модуля Go файлы находятся в одном пакете. Разделяйте их на подпакеты, когда появится реальная необходимость, а не для заполнения дерева каталогов.

## Что пока не включено

В шаблоне нет платёжных интеграций, AI-провайдеров, очереди фоновых задач, поиска, аналитики и продуктовой админки. Их настройка зависит от задачи. Redis, API и модульная структура дают место для расширения без обязательных внешних аккаунтов.

`/readyz` проверяет PostgreSQL, Redis и S3. Доступность Keycloak во время работы в эту проверку не входит: уже выданные токены могут проверяться по закешированным ключам. Новые входы и обновление сессии при недоступном Keycloak временно не работают.
