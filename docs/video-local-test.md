# Проверка видеовстреч на двух ноутбуках без деплоя

Это отдельный инструмент `tools/video-test.html`, а не часть продуктового интерфейса. Он работает через HTTPS helper `scripts/video-test-server.mjs`; открывать HTML как `file://` нельзя. Внутри страницы есть кнопка «Как проверить на двух ноутбуках» с инструкцией. Понадобятся Node.js, работающий Docker, mkcert и Chrome на двух ноутбуках. Интернет нужен для загрузки закреплённого SDK `livekit-client@2.23.0` с CDN.

## Первый ноутбук

Узнайте его локальный IPv4. Ниже `192.168.1.10` — пример, замените его своим адресом. Второй ноутбук должен видеть именно этот адрес; `localhost` относится к самому второму ноутбуку.

Из корня проекта:

```sh
make setup
mkdir -p .local/video-test
mkcert -install
mkcert -cert-file .local/video-test/cert.pem -key-file .local/video-test/key.pem 192.168.1.10 localhost 127.0.0.1
```

Создайте отдельный файл настроек. Команда генерирует секреты сразу в файл с правами 0600 и не печатает их:

```sh
node --input-type=module - 192.168.1.10 <<'NODE'
import { randomBytes } from 'node:crypto';
import { writeFileSync, existsSync } from 'node:fs';
const ip = process.argv[2];
const filename = '.local/video-test/video.env';
if (existsSync(filename)) throw new Error('video.env уже существует: сохраните его ключи или удалите файл явно');
writeFileSync(filename, [
  `LIVEKIT_NODE_IP=${ip}`,
  `LIVEKIT_URL=wss://${ip}:9443/livekit`,
  `LIVEKIT_API_KEY=${randomBytes(12).toString('hex')}`,
  `LIVEKIT_API_SECRET=${randomBytes(32).toString('hex')}`,
  'LIVEKIT_IMAGE=REPLACE_WITH_VERIFIED_IMAGE',
  '',
].join('\n'), { mode: 0o600 });
NODE
```

Откройте `.local/video-test/video.env` локально. Замените `REPLACE_WITH_VERIFIED_IMAGE` на `livekit/livekit-server:<проверенный тег>` или `livekit/livekit-server@sha256:<проверенный digest>` из [официальных релизов](https://github.com/livekit/livekit/releases). У файла нет выдуманного тега или незакреплённого `latest`. При изменении IP обновите `LIVEKIT_URL`, `LIVEKIT_NODE_IP` и перевыпустите сертификат.

Поднимите инфраструктуру и обновлённые контейнеры. Не пропускайте миграции: старый образ events не знает онлайн формата.

```sh
docker compose --env-file .env --env-file .local/video-test/video.env -f compose.yaml -f compose.video.yaml --profile app --profile video up -d --build events-migrate events-service identity-migrate identity-service gateway-service livekit
```

Compose поднимет необходимые зависимости. events-service и LiveKit получат одинаковые ключи из второго env-файла. Дополнительный файл нужно указывать при каждом таком запуске. Для проверки готовности используйте кнопку «Проверить gateway» в тестовой странице.

Запустите временный HTTPS helper:

```sh
node scripts/video-test-server.mjs --lan \
  --cert .local/video-test/cert.pem --key .local/video-test/key.pem \
  --origin https://192.168.1.10:9443 \
  --gateway http://127.0.0.1:8080 \
  --app-origin http://localhost:3000 \
  --livekit http://127.0.0.1:7880
```

`--app-origin` должен точно совпадать с `APP_ORIGIN` gateway. Значение выше подходит для стандартного локального setup. Helper сначала проверяет настоящий Origin своего сайта и только после этого подставляет APP_ORIGIN для gateway CSRF. CORS и CSRF приложения ослаблять не нужно. Без `--lan` helper слушает только loopback и не принимает сетевой origin.

## Доверие сертификату на втором ноутбуке

На первом выполните `mkcert -CAROOT`. Из указанного каталога передайте второму ноутбуку **только `rootCA.pem`**. Установите его в доверенные корневые сертификаты сайтов средствами ОС/Chrome. На macOS — «Связка ключей», System/Система, доверять для SSL; на Windows — Trusted Root Certification Authorities; на Linux — системное хранилище и при необходимости хранилище сертификатов используемого браузера. Перезапустите Chrome.

**Не передавайте `rootCA-key.pem` и `.local/video-test/key.pem`: это закрытые ключи.** Принимайте CA только от своего первого ноутбука. После проверки удалите тестовый CA из доверенных второго ноутбука, если он больше не нужен.

Оба ноутбука должны открывать `https://192.168.1.10:9443` без предупреждений сертификата. Простого «продолжить на небезопасный сайт» недостаточно для надёжной проверки камеры и WebSocket.

## Сценарий

1. Первый ноутбук: зарегистрируйте отдельную учётную запись, нажмите «Создать онлайн встречу на час», затем «Присоединиться к звонку». Начало будет через две минуты, окно видео уже открыто. Формат online задаётся сразу при создании — смена формата после открытия входа запрещена.
2. Нажмите «Скопировать ссылку второму ноутбуку». В URL только UUID мероприятия, без сессионных cookie и видеобилетов.
3. Второй ноутбук: откройте ссылку, зарегистрируйте другого пользователя, нажмите «Записаться на встречу», затем «Присоединиться к звонку».
4. На каждом нажмите «Включить микрофон» и «Включить камеру», выдайте разрешения Chrome. При необходимости нажмите «Разрешить звук». Проверьте, что слышите и видите другого участника. Используйте наушники.
5. Проверьте список участников, демонстрацию экрана и выход из звонка. После выхода камера и микрофон должны выключиться.

Тест действительно создаёт аккаунты и мероприятие в локальной базе. Инструмент не записывает медиа. Он не читает `.env`, не выводит пароли/JWT и не хранит их в localStorage. Пароль очищается из формы после попытки входа. При ошибке API журнал показывает только HTTP-статус. Для последующих подключений выдаётся новый билет; обычный JWT живёт до двух минут.

## Сеть и ограничения

На первом ноутбуке разрешите входящие TCP 9443, TCP 7881 и UDP 7882. TCP 9443 обслуживает HTTPS и сигналинг через helper; медиа идут напрямую на LiveKit. Разрешите входящие подключения Docker Desktop. Отключите AP/client isolation в Wi-Fi либо используйте одну проводную сеть. Проброс портов роутера в интернет не требуется. PostgreSQL, Redis, S3 и внутренние HTTP-сервисы второму ноутбуку не открываются.

Если соединение устанавливается, но медиа отсутствуют, проверьте `LIVEKIT_NODE_IP`, Docker UDP forwarding, firewall и изоляцию сети. Для сложного NAT и корпоративных фильтров потребуется TURN/TLS — этот локальный стенд его не настраивает. Инструмент не подтверждает работоспособность через произвольные внешние сети.

После проверки завершите helper через Ctrl+C. Он предназначен только для временного доверенного LAN-теста, не для production. Для медиасервера и ограничений отзыва уже подключённых участников см. [video.md](video.md). SDK вызовы сверены с [официальным JS SDK 2.23.0](https://docs.livekit.io/reference/client-sdk-js/).
