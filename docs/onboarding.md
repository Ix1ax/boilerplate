# Обучение интерфейсу

Общий механизм на driver.js — `client/src/features/onboarding`, сценарии — `model/constants.ts` внутри этой фичи. В дашборде обучение автоматически показывается при первом входе пользователя. Кнопка «Обучение» позволяет запустить его повторно.

## Добавить сценарий

1. Отметьте реальные элементы устойчивыми атрибутами `data-tour="files-upload"`. Не используйте CSS-классы оформления в качестве селекторов.
2. Опишите сценарий в `features/onboarding/model/constants.ts` и экспортируйте его через публичный `features/onboarding/index.ts`. Внутри фичи импортируйте тип `Tour` напрямую из `model/types`, не через собственный публичный API. Сценарии используют только имена `data-tour` и не импортируют страницы или widgets. Слой `app` подключает готовые сценарии и хук, не содержит шагов и текстов обучения.
3. В компоненте страницы или layout вызовите хук и подключите кнопку:

```tsx
import { useLocation } from 'react-router';
import { useTour, type Tour } from '@/features/onboarding';
import { Button } from '@/shared/ui';

const filesTour = {
  id: 'files-intro',
  version: 1,
  steps: [
    {
      target: 'files-upload',
      title: 'Добавьте документ',
      description: 'Загрузите файл для дальнейшей работы.',
    },
  ],
} satisfies Tour;

// Внутри компонента; user — текущий пользователь из useCurrentUser().
const location = useLocation();
const { start, running } = useTour(filesTour, user?.id, location.pathname);
// В JSX:
<Button disabled={!user || running} onClick={() => void start()}>
  Обучение
</Button>;
```

Шаг без `target` показывает вводное сообщение по центру. Тексты считаются обычным текстом: HTML экранируется. Скрытые и отсутствующие элементы исключаются при старте, поэтому шаг для админской вкладки виден только при наличии вкладки. Права по-прежнему проверяет сервер.

## Жизненный цикл и хранение

Смена `scope` (обычно pathname), пользователя, id или версии сценария закрывает тур; размонтирование отменяет ожидающую загрузку. Движок загружается динамически при запуске. При первом показе сохраняется `started`, закрытие через крестик, Escape или фон меняет его на `dismissed`, нажатие «Готово» — на `completed`. Программное закрытие при навигации оставляет прежний статус, поэтому уже показанное обучение не запускается заново.

`getTourStatus(tour, userId)` возвращает результат или `null`. Для автозапуска передайте четвёртым аргументом `useTour` значение `true` (по умолчанию выключен). Тур стартует после отрисовки только при отсутствии сохранённого статуса; сбой загрузки или отсутствие целей не считается показом. Повторный ручной запуск разрешён всегда. При существенном изменении шагов увеличивайте `version`: новая версия автоматически показывается один раз.

Результаты локальны для браузера и пользователя, не синхронизируются с сервером. Чтение и запись идут через `readLocalStorage` / `writeLocalStorage` из `shared/lib`: обёртка логирует ошибки и при запрете localStorage сохраняет результат в памяти до перезагрузки страницы. В хранилище нет токенов или содержимого пользовательских записей.

## Границы заготовки

Делайте короткие сценарии на 3–7 шагов для уже отрисованного интерфейса. Загружаемые данные должны появиться до запуска. Сценарий не переключает маршруты и не открывает диалоги: для каждого раздела лучше отдельный тур. Если понадобится обучение действием, расширяйте механизм явной подготовкой шага и ожиданием элемента, а не таймерами в страницах.

Оформление использует токены темы, анимация учитывает `prefers-reduced-motion`; после закрытия возвращается фокус. После добавления сценария проверяйте клавиатуру (Tab, Shift+Tab, Escape), узкий экран, обе темы, обе роли и уход со страницы во время тура.
