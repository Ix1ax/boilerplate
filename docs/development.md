# Разработка

## Новый предметный модуль

1. Добавьте SQL-миграцию с секциями `-- +goose Up` и `-- +goose Down`.
2. Новый домен — отдельный сервис. Скопируйте `server/tasks` как шаблон (свой `go.mod`, база, миграции, Dockerfile), замените домен.
3. Добавьте сервис в `compose.yaml` (с `<имя>-migrate`), адрес в `Upstreams` gateway и маршрут-прокси в `server/gateway/internal/httpapi`.
4. Ограничьте SQL владельцем или членством в команде. UUID не даёт права доступа.
5. Согласованно обновите OpenAPI, типы и Zod-схемы в `packages/contracts`.
6. Добавьте чтение в `entities`, действия в `features`, страницы в `pages`.
7. Проверьте сценарий, ошибки и попытку доступа из другого аккаунта.

## Команды

Используйте npm из корня: один `package-lock.json` для всех workspaces.

```sh
npm install имя-пакета -w @starter/client
make check
make integration
make smoke
```

`make integration` требует `.env`, PostgreSQL и Redis: проверяет миграции, владельцев, пагинацию и полный цикл браузерной сессии с тестовым OIDC-сервером. Smoke требует работающий стек и двух демопользователей. Клиент `hackathon-cli` с password grant предназначен только для локальной проверки API, production setup исключает его из нового realm; в существующем realm удалите его вручную.

Для Go: у каждого сервиса свой модуль, команды запускаются в его каталоге.

```sh
cd server/tasks   # или server/gateway, server/files
go get путь/пакета
go mod tidy
```

Инфраструктура (`make infra`): `tasks-postgres` на :5433, `files-postgres` на :5434, `rabbitmq` на :5672 (консоль http://localhost:15672, логин и пароль в `.env`). Запуск сервисов вне Docker (после `make infra`): `make gateway`, `make tasks`, `make files`; tasks слушает :8081, files — :8082 (в `.env` для этого заданы `TASKS_URL` и `FILES_URL`).

Миграции есть у каждого сервиса и применяются к его базе: `make migrate`, состояние: `make migrate-status`. Добавляйте новую миграцию вместо редактирования применённой. Откат (`go run ./cmd/tasks migrate down` после загрузки `.env` с `DATABASE_URL=$TASKS_DATABASE_URL`) может удалить данные.

## Ошибки хранилища Docker Desktop

Если сборка останавливается с `input/output error` в `/var/lib/docker/buildkit/*.db` до выполнения Dockerfile, проверьте `df -h /` и состояние Docker Desktop. После заполнения диска сначала освободите место на Mac, затем перезапустите Docker Desktop (`docker desktop restart`) и повторите `make up`. Для чистой сборки всего стека оставляйте запас свободного места под зависимости и слои образов.

`docker system df` показывает объём образов, томов и кеша, если хранилище доступно. При необходимости `docker builder prune` удаляет неиспользуемый кеш сборки: следующие сборки займут больше времени. Не используйте удаление `Docker.raw`, factory reset или очистку volumes для устранения этой ошибки — это может удалить базы и модель. Если ошибка записи сохраняется после освобождения места и перезапуска, сначала сохраните данные и соберите диагностику Docker Desktop.

## Фронтенд

Две самостоятельные SPA — `client` (`/`) и `admin` (`/admin/`), общий origin и gateway. `npm run dev` / `make web` запускает обе; открывайте admin через `http://localhost:3000/admin/`. Сборки независимы: `npm run build:client` и `npm run build:admin`. Детали границ, Docker и браузерной проверки — [microfrontends.md](microfrontends.md).

Vite, React Router, React Query, React Hook Form, Zod и Tailwind v4. `@/` указывает на `src`. Импорты только вниз по `app → pages → widgets → features → entities → shared`; ESLint проверяет алиасные импорты между слоями. Схема создания задачи и DTO берутся из `@starter/contracts`.

Основной UI находится в `shared/ui` на Base UI, тема — `src/app/globals.css`. Независимый `@starter/ui` на Radix сохранён как дополнительный набор. Сообщения и документация — по-русски. Ошибки загрузки показывайте с повтором, серверные ошибки читайте из `error.message`.

Браузер не читает токены: запросы идут на `/api/v1` с cookie, вход — навигацией на `/auth/login`. Пользователь загружается из `/me`, отсутствие сессии возвращает null в query. Пользовательские данные React Query очищаются при успешном выходе, затем происходит полная навигация.

Главная доступна гостям. Она проверяет сессию через `/me` и запрашивает защищённые `/events` и `/sports` только после подтверждения входа (`enabled`). Для гостя направления ведут в поиск по названию; вход требуется при переходе к каталогу. Не вызывайте защищённые запросы с публичного экрана до проверки сессии: глобальный обработчик `401` отправляет на вход.

### Хуки сущностей

Хуки каждой сущности объединяем в `entities/<сущность>/model/hooks.ts`, включая хуки React Query. Отдельные `use*.ts` внутри entity не создаём, даже если хук пока один. Типы, ключи запросов и преобразования остаются в `types.ts`, `constants.ts` и `mappers.ts`. Хуки экспортируем через `model/index.ts` и публичный `index.ts` сущности; потребители импортируют их из публичного API слайса.

Это правило действует в обеих SPA (`client` и `admin`). Оно объединяет хуки внутри одной сущности, без общего файла для всего слоя `entities`. В сущностях без `model/index.ts` публичный `index.ts` экспортирует хуки непосредственно из `./model/hooks`.

### Плавная прокрутка главной

`shared/hooks/useSmoothScroll.ts` создаёт Lenis через `useEffect`; хук вызывается только в `HomePage`. Колесо и трекпад сглаживаются через `lerp: 0.12`, касания остаются нативными. Включены якоря, вложенные области прокрутки и остановка инерции при навигации. При уходе с главной очистка эффекта уничтожает экземпляр и цикл кадров. При `prefers-reduced-motion` или «Остановить анимации» в виджете доступности экземпляр Lenis не создаётся. Для локального исключения области из сглаживания используйте `data-lenis-prevent`.

### Заставка при открытии

`client/src/app/loading/BrandIntro.tsx` показывает фирменную заставку при каждом открытии приложения; это отдельный экран: страница, уведомления и виджет доступности монтируются после его завершения. Стили задаются Tailwind-классами в компоненте, а сценарий и тайминги — токенами `--animate-intro-*` и ключевыми кадрами в `@theme` файла `client/src/app/styles/globals.css`: падение готового знака сверху → мягкое приземление → подброс билета → сдвиг знака → буквы. Билет подбрасывается, после раскрытия букв логотип остаётся по центру. Заставка вместе со сплошной жёлтой подложкой плавно исчезает; кнопки пропуска нет. При `prefers-reduced-motion` или отключении анимации в виджете доступности показывается статичный логотип на 200 мс.

После изменения исходников для Docker нужна пересборка: `docker compose build web-service && docker compose up -d --no-deps web-service`. Для разработки используйте `make web`, предварительно остановив `web-service`, занимающий порт 3000.

## Конфигурация

| Файл                                   | Назначение                   |
| -------------------------------------- | ---------------------------- |
| `.env.example`                         | Корневой шаблон без секретов |
| `.env`                                 | Compose и Go через Makefile  |
| `client/.env.example`                  | Публичные настройки Vite     |
| `client/.env.local`                    | Локальные настройки Vite     |
| `.local/keycloak/hackathon-realm.json` | Первый импорт Keycloak       |

`make setup` создаёт отсутствующие настройки и сохраняет существующие значения. Пароли генерируются hex-строками, подходящими для DATABASE_URL; `.env` имеет права 0600. При ручной смене пароля учитывайте URL-кодирование и shell-синтаксис: Makefile загружает `.env` как shell-файл.

Серверный `scripts/setup.mjs --production` запускается контейнером в `deploy/deploy.sh`: проверяет `APP_DOMAIN`/`AUTH_DOMAIN`, включает HTTPS-настройки и генерирует недостающие секреты. Полный порядок — [deployment.md](deployment.md). Локальные проверки сохраняются; Actions выполняет только деплой при push в `main`.

`VITE_*` попадает в браузерную сборку: секреты там запрещены. API_URL по умолчанию `/api/v1`, WS_URL пустой: сервер WebSocket пока отсутствует. OIDC-переменные и APP_ORIGIN читает Go, в Docker они задаются окружением API.

Настройки realm импортируются только в пустую базу Keycloak. Повторный setup не меняет сохранённый realm и пароли существующих пользователей. После смены порта приложения обновите в существующем клиенте `hackathon-web` поля Valid redirect URIs (`http://localhost:3000/auth/callback`), Web origins (`http://localhost:3000`) и Valid post logout redirect URIs (`http://localhost:3000/`) через административную консоль Keycloak на `http://localhost:8180`. Удалять базу для смены адресов не нужно.

Перед показом проверьте браузером: вход, задачу, завершение, пагинацию, файл, перезагрузку, выход и вход другим пользователем. Проверьте также сетевую ошибку, истечение сессии и недоступность чужих записей.
