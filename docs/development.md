# Разработка

## Добавить предметный модуль

Возьмите `tasks` как пример. Для нового ресурса:

1. Добавьте SQL-миграцию, например `00002_projects.sql`, с секциями `-- +goose Up` и `-- +goose Down`.
2. Создайте пакет в `apps/api/internal/` с моделью, сервисом, репозиторием и HTTP-маршрутами.
3. Подключите маршруты в `internal/httpapi/server.go` к группе `/api/v1` после авторизации.
4. Ограничьте запросы к данным владельцем или членством в команде. UUID записи сам по себе не даёт права доступа.
5. Опишите эндпоинты в OpenAPI, типы и входные схемы — в `packages/contracts`.
6. Во фронтенде добавьте API ресурса в `entities`, форму или действие — в `features`, композицию страницы — в `screens`.
7. Проверьте основной сценарий, ошибки валидации и попытку доступа из другого аккаунта.

В шаблоне Go-модель и TypeScript-типы поддерживаются вручную. Если API вырастет, подключите генерацию по OpenAPI и проверку расхождений в CI.

## Миграции

```sh
make migrate
make migrate-status
```

Откат последней миграции выполняется явно:

```sh
set -a
. ./.env
set +a
cd apps/api
go run ./cmd/migrate down
```

Откат может удалить данные. Для обычной разработки добавляйте новую миграцию, исправляющую схему. Запуск `make up` тоже применяет ожидающие миграции; API не меняет схему самостоятельно.

## Фронтенд

Импорты из `src` используют `@/`. Общие компоненты импортируются из `@starter/ui`, схемы и типы — из `@starter/contracts`. Серверные модули авторизации помечены `server-only` и не должны попадать в клиентские компоненты.

Формы используют React Hook Form и Zod. Ошибки должны быть видимы рядом с действием; не ограничивайтесь сообщением в консоли. Пример есть в `features/create-task`.

Для нового общего UI-компонента добавьте файл в `packages/ui/src`, затем экспорт в `index.ts`. Токены находятся в `styles.css`; меняйте палитру там, чтобы светлая и тёмная темы оставались согласованными. Для компонентов с интерактивностью указывайте `'use client'` на границе клиентского кода.

Тексты интерфейса, сообщения об ошибках и пояснения пишем по-русски. Комментарий должен объяснять причину решения или ограничение. Очевидные действия кода комментировать не нужно.

## Зависимости

Устанавливайте пакеты из корня монорепы:

```sh
npm install имя-пакета -w @starter/web
npm install имя-пакета -w @starter/ui
```

Для Go:

```sh
cd apps/api
go get путь/пакета
go mod tidy
```

В шаблоне используются версии исходного проекта, с которым работала команда. Это не обещание, что каждая из них последняя. Перед новым хакатоном обновите зависимости отдельным изменением и запустите проверки.

## Проверки

`make check` не требует запущенных сервисов. Unit-тесты проверяют JWT, границы BFF, обработку API-ошибок и валидацию.

`make integration` работает с настоящим PostgreSQL: применяет миграции, создаёт данные с уникальным владельцем и удаляет их после теста. Проверяются пагинация и недоступность чужих записей. Используйте локальную или отдельную тестовую базу.

`make smoke` проверяет запущенный стек: два аккаунта, JWT, роли, CRUD, приватность задач и файлов, S3 и запрет чужого Origin в BFF. Для входа служит отдельный клиент `hackathon-cli`, разрешённый только в локальном realm. На сервере его надо удалить или выключить.

Проверка браузерного входа: открыть приложение, войти, создать задачу, отметить её, загрузить файл, обновить страницу, выйти и войти вторым пользователем. У второго пользователя список должен быть пустым, чужой файл должен возвращать 404.

## Конфигурация

| Файл                                   | Кто читает                           |
| -------------------------------------- | ------------------------------------ |
| `.env`                                 | Compose и команды Go в Makefile      |
| `apps/web/.env.local`                  | Next.js при разработке на компьютере |
| `.local/keycloak/hackathon-realm.json` | Keycloak при первом импорте          |
| `infra/keycloak/realm.template.json`   | Скрипт `setup`                       |

Автоматически созданные пароли состоят из шестнадцатеричных символов и подходят для URL подключения. Если меняете пароль базы вручную, корректно закодируйте его в `DATABASE_URL`; Makefile читает `.env` как shell-файл.

Файл импорта realm доступен контейнеру для чтения, но пароли в него не записываются: Keycloak подставляет их из переменных окружения. Сами значения остаются в `.env` с правами `0600`.

`NEXT_PUBLIC_*` виден браузеру. Секреты в таких переменных хранить нельзя. Здесь настройки OIDC и upstream передаются только серверной части Next.js.

## Предупреждение в зависимостях линтера

На 16 октября 2026 года `npm audit` сообщает об уязвимости `braces` в цепочке `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch`. Исправленной версии `braces` для этого предупреждения пока нет; подробности — в [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).

Цепочка относится к инструментам разработки, которые обрабатывают локальные пути при запуске линтера. Файловые шаблоны из запросов пользователей в этот код не передаются. Перед использованием шаблона в новом проекте повторите `npm audit` и проверьте доступные обновления. Не применяйте `npm audit fix --force` без проверки: сейчас он предлагает сменить основную версию конфигурации Next.js.

Для PostCSS в `package.json` задан override на 8.5.29: он заменяет устаревшую вложенную версию Next.js. Причина обновления описана в [GHSA-fxqj-rqcc-2cmp](https://github.com/advisories/GHSA-fxqj-rqcc-2cmp). После обновления самого Next.js проверьте, нужен ли override ещё.
