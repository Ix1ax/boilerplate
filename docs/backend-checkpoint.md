# Расширение бэкенда: состояние и оставшиеся проверки

Контрольная точка 19 октября 2026 года. Работа выполнена поверх `43d781b`, изменения пока не закоммичены. Продуктовый frontend не менялся. Пользователь попросил продолжить проверки в отдельном чате и подготовить самостоятельный HTML-стенд для видеосвязи.

## Реализовано

| Возможность | Основные файлы | Проверка |
| --- | --- | --- |
| Встреча из спроса: минимум три человека, общий слот, первый организатор, приглашения без автозаписи | `demand_proposals*.go`, миграция `00006` | Реальный PostgreSQL, гонка claim |
| Отметки прибытия и опоздания, приватная сводка | `arrival.go` | Окно времени, права, реальные БД |
| Друзья и личные чаты с историей | `social*.go`, миграция `00007` | Чужой доступ, удаление дружбы, пагинация |
| Отзывы после завершения мероприятия | `social_repository.go` | Право автора, срок, один отзыв |
| Истории на сутки: текст, фото/видео, отдельный S3-бакет | `social_media.go`, `social_storage.go` | ACL и очистка на фейковом blob-хранилище; реальный S3 ещё проверить |
| Клубы | Допущенные organizations + memberships | Членство не даёт права управления |
| Онлайн/офлайн и короткие билеты LiveKit | `online*.go`, миграция `00008`, `compose.video.yaml` | Подпись, grants, сроки, доступ на реальном PostgreSQL |
| Персональные рекомендации | `recommendations*.go`, миграция `00009` | Cold start, интересы, приватность, скрытие и исключение уже записанного |
| Личный прогресс | `progress.go` | Очки из действующих данных; повтор запроса ничего не начисляет |

Чат мероприятия — уже существующие comments, отдельная история не дублируется. Список чатов содержит ссылки на такие обсуждения. WebSocket передаёт сигналы изменений, история читается через API. Продуктовому frontend ещё потребуется подключение новых API.

## Дополнительные исправления

- Конкурирующие PATCH теперь дают 409 вместо потери чужой правки.
- Напоминания перечитывают актуальное состояние под блокировкой.
- Истёкший запрос компании можно заменить новым.
- По прошедшему событию нельзя принять заявку.
- При исключении проводника освобождаются и переназначаются пары, отправляются уведомления.
- Админская очередь организаций по умолчанию включает все статусы.
- Production setup не создаёт демопользователей и сохраняет production при повторном запуске без флага.
- Смена пароля использует атомарный отзыв Redis-сессий, независимый контекст, ошибки 503 и долговечный `password_changed_at` из identity; уже закешированный статус действует максимум 30 секунд.

## Известные границы

- LiveKit настроен как отдельный медиасервер; UDP/WebRTC не проксируется через HTTP gateway. Публичные API идут через gateway. Для сложных NAT нужен TURN.
- Видео-JWT живёт до двух минут. Истечение запрещает новый вход, но не отключает уже подключившегося. Немедленный отзыв текущего звонка потребует RoomService с надёжной доставкой действий; это ещё не реализовано.
- Подбор спроса ограничен 1000 кандидатами и 20 людьми в группе; обновляется минутным заданием и при чтении. Место не выдумывается и подтверждается организатором.
- Рекомендации — объяснимые правила, а не обученная модель: до 1000 ближайших по времени кандидатов в горизонте 60 дней. Offset относится к текущей подборке, не к сохранённому снимку. Есть soft-предпочтения времени, жёсткие фильтры уровня/радиуса и запрет скрытых событий. Отдельные метрики качества на живых пользователях ещё не измерены.
- Посещение не подтверждается. Очки отражают записи и действия, без продажи, обмена и рейтинга людей.
- Внешняя почта/MAX всё ещё best effort без отдельного delivery-outbox; аудит также допускает потери. Старый риск publisher confirms при отсутствии очереди подписчика не исправлялся в этой итерации.
- Видео, истории и прочие новые функции ещё не подключены к продуктовому frontend: это сознательная граница задачи.
