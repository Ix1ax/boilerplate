# Онлайн встречи

Привязка к кейсу: дополнительные возможности и развитие архитектуры. Видеокомната принадлежит мероприятию; его обсуждение остаётся сохранённым чатом. Формат хранится в `events.format`, по умолчанию `offline`.

API через gateway:

| Запрос | Назначение |
| --- | --- |
| `GET /api/v1/events/{id}/format` | Формат события, если пользователь вправе видеть карточку |
| `PUT /api/v1/events/{id}/format` | `{ "format": "online" }` или `offline`; только организатор опубликованной встречи до `starts_at - 15 минут` |
| `POST /api/v1/events/{id}/video/token` | Короткий билет в комнату `event_<uuid>` |

Смена формата уведомляет подтверждённых участников, ожидающих решения и лист ожидания через transactional outbox. Повтор установки того же значения не создаёт дублей. Права администратора приложения не дают вход в частный звонок.

Билет получает только организатор или подтверждённый участник опубликованного онлайн события. Окно выдачи открывается за 15 минут до начала и закрывается в `ends_at`; без окончания встреча длится 90 минут. JWT HS256 живёт не больше двух минут и не выходит за окончание события. У него только доступ в конкретную комнату и передача медиа; нет управления комнатами, записи звонка и произвольного обмена данными в обход сохраняемого чата.

## Настройка

Сервису events нужны три переменные: `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`. Ключи должны совпадать с медиасервером. Секрет — минимум 32 символа из криптографического генератора, без значения по умолчанию. Отсутствие конфигурации не мешает обычным мероприятиям; билет возвращает 503. Для внешнего доступа URL обязательно `wss://`; `ws://` разрешён лишь на localhost и 127.0.0.1.

Дополнительный `compose.video.yaml` запускает медиасервер профилем `video`. До запуска задайте `LIVEKIT_IMAGE` с проверенной версией или digest и `LIVEKIT_NODE_IP` с доступным участникам адресом. Команда: `docker compose -f compose.yaml -f compose.video.yaml --profile video up -d livekit`. Секреты в `.env` или secret manager, не в репозитории.

Сигналинг 7880 опубликован только на loopback; перед ним нужен TLS reverse proxy с WebSocket Upgrade и публичным доменом. Для медиа открываются TCP 7881 и UDP 7882. Для сложных NAT и корпоративных сетей потребуется TURN/TLS; это отдельная настройка домена, сертификата и firewall по [официальному руководству LiveKit](https://docs.livekit.io/transport/self-hosting/deployment/). API приложения ходит через gateway; медиа идут в LiveKit напрямую — проксирование UDP через HTTP gateway невозможно. Эта оговорка относится только к WebRTC.

## Граница отзыва доступа

Истечение JWT запрещает новый вход, но само по себе не завершает текущую медиасессию. После отмены события или исключения участника новые билеты не выдаются. Уже выданный билет допускает вход ещё максимум две минуты, существующее подключение продолжится. Для немедленного отключения при модерации и строгого завершения в `ends_at` нужна интеграция LiveKit RoomService `RemoveParticipant`/`DeleteRoom` с надёжным повтором через outbox. До её подключения нельзя обещать мгновенный отзыв видео доступа. Видеозапись и хранение медиа не включены.

Проверки в коде покрывают роль, статус, формат, границы времени, TTL, подпись и отсутствие административных grants; интеграционный тест проверяет доступ на реальном Postgres. Проверка медиапотока двух внешних участников требует поднятого LiveKit, TLS и настроенного маршрута UDP/TURN.

Формат JWT и grants сверены с [исходниками протокола LiveKit](https://github.com/livekit/protocol/blob/main/auth/grants.go); параметры контейнера — с [официальным конфигом](https://github.com/livekit/livekit/blob/master/config-sample.yaml).
