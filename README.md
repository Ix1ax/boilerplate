# Стартовая монорепа для хакатонов

Основа следующего проекта на стеке нашей команды: Next.js, TypeScript и Go. Здесь есть вход через Keycloak, задачи пользователя в PostgreSQL, приватные файлы в S3, Redis, общий UI и проверки. Предметной области прошлого хакатона здесь нет.

Папка самостоятельная: её можно скопировать в новый каталог и работать без исходного репозитория. В исходном проекте эта папка исключена из Git. Внешние сервисы, домены и секреты старого проекта не используются.

## Быстрый старт

Понадобятся Docker Desktop с Compose v2 и Node.js 24. Для разработки API на компьютере нужен Go 1.26; версия указана в `apps/api/go.mod`. Версии npm-зависимостей зафиксированы в `package-lock.json`.

Все команды ниже выполняются из этой папки.

```sh
make up
```

Команда создаст локальную конфигурацию, соберёт приложения, применит миграции и дождётся готовности сервисов. При первом запуске Docker скачает образы, а сборка установит зависимости. Данные сохраняются в отдельных томах Compose.

Откройте [приложение](http://localhost:13000). Зарегистрируйтесь или войдите с `DEMO_EMAIL` и `DEMO_PASSWORD` из `.env`. Пароли генерируются при первом `make setup`; в шаблоне нет общего пароля для всех копий.

| Сервис         | Адрес                         |
| -------------- | ----------------------------- |
| Приложение     | http://localhost:13000        |
| Go API         | http://localhost:18080        |
| Готовность API | http://localhost:18080/readyz |
| Keycloak       | http://localhost:18180        |
| Письма Mailpit | http://localhost:18025        |
| PostgreSQL     | localhost:15432               |
| Redis          | localhost:16379               |
| S3 API         | http://localhost:18333        |

Порты отличаются от портов исходного проекта. Имя Compose-проекта — `hackathon-starter`, его можно поменять в `.env`. Две копии шаблона на одном компьютере потребуют разных имён **и** портов.

```sh
make logs    # Смотреть логи
make down    # Остановить сервисы, сохранив данные
```

`make up` запускает локальное окружение. Подготовка серверного окружения описана в [docs/deployment.md](docs/deployment.md).

## Что уже работает

- Вход и регистрация в Keycloak: Authorization Code с PKCE, проверка `state`, обновление сессии, выход.
- Токены доступны серверной части Next.js через HttpOnly cookies. В браузерный JavaScript они не передаются.
- Go API проверяет подпись JWT, issuer, audience и срок действия. Пример проверки роли `admin` — `GET /api/v1/admin/ping`.
- Задачи: создание, список с пагинацией, завершение и удаление. Любая операция в базе ограничена владельцем записи.
- Файлы: загрузка в закрытое S3-хранилище, скачивание через API с проверкой владельца. До 10 МиБ, с проверкой фактического типа содержимого.
- Redis ограничивает изменяющие запросы: 60 в минуту на пользователя. Лимит общий для экземпляров API; при недоступности Redis запись временно закрывается.
- Логи в JSON, идентификатор запроса, `/healthz`, `/readyz`, таймауты и корректное завершение API.
- Общий пакет из 33 UI-компонентов: поля, кнопки, формы, диалоги, вкладки, выпадающие меню, состояния загрузки и другие блоки.
- Светлая и тёмная темы, React Hook Form и Zod, состояния ошибок, адаптивная страница с рабочими примерами.
- SQL-миграции Goose, многоэтапные Docker-сборки, запуск контейнеров приложений без root.
- Unit-тесты, интеграционный тест PostgreSQL, проверка работающего API и шаблон GitHub Actions.

## Структура

```text
apps/
  api/
    cmd/api/                  # Запуск сервера
    cmd/migrate/              # Запуск миграций
    internal/
      auth/                   # Проверка JWT и ролей
      config/                 # Настройки окружения
      database/migrations/    # SQL-миграции, встроенные в бинарник
      files/                  # Работа с приватными файлами
      httpapi/                # Маршруты и общие middleware
      platform/               # PostgreSQL, Redis, S3
      tasks/                  # Пример предметного модуля
  web/
    src/
      app/                    # Маршруты, BFF, вход и callback
      screens/                # Композиция страниц
      features/               # Действия пользователя и формы
      entities/               # API предметной области
      shared/                 # HTTP-клиент, авторизация, хуки
packages/
  ui/                         # Компоненты и общие CSS-токены
  contracts/                  # Типы, Zod-схема и OpenAPI
infra/                        # Локальные настройки Keycloak и PostgreSQL
deploy/                       # Пример конфигурации Caddy
scripts/                      # Подготовка окружения, экспорт и проверка API
docs/                         # Архитектура, разработка, сервер, план старта
.github/                      # CI и шаблон pull request
```

Npm workspaces связывают `apps/web` и `packages/*`. Go API остаётся отдельным модулем. Команды верхнего уровня находятся в Makefile; дополнительный оркестратор сборки не нужен.

## Разработка на компьютере

```sh
make install   # Настройки, npm ci и Go-модули
make infra     # PostgreSQL, Redis, S3, Mailpit и Keycloak
make migrate   # Миграции через подключение с компьютера
```

Затем в двух терминалах:

```sh
make api
```

```sh
make web
```

В этом режиме фронтенд работает на том же порту 13000, что и Docker-вариант. Контейнер `web` при этом должен быть остановлен; для API аналогично. Если до этого запускали весь стек, выполните `make down`, затем команды выше.

Go читает корневой `.env` через Makefile. Next.js читает `apps/web/.env.local`; его создаёт `make setup`. Docker получает значения из корневого `.env` и заменяет внутренние адреса в `compose.yaml`.

`make setup` сохраняет существующие пароли и `apps/web/.env.local`. Изменения redirect URI в шаблоне realm будут применены только при первом импорте нового realm. Для уже работающего Keycloak используйте его админку.

## Команды и проверки

| Команда               | Что делает                                                 |
| --------------------- | ---------------------------------------------------------- |
| `make setup`          | Создаёт `.env`, локальный realm и настройки Next.js        |
| `make install`        | Устанавливает npm- и Go-зависимости                        |
| `make up`             | Собирает и запускает весь стек в Docker                    |
| `make infra`          | Запускает зависимости для разработки на компьютере         |
| `make migrate`        | Применяет миграции с компьютера                            |
| `make migrate-status` | Показывает состояние миграций                              |
| `make check`          | Тесты, Go vet, сборка, TypeScript, ESLint, форматирование  |
| `make integration`    | Проверяет репозиторий на настоящем PostgreSQL              |
| `make smoke`          | Проверяет запущенный API, авторизацию, права, файлы и CSRF |
| `make fmt`            | Форматирует Go, TypeScript и документацию                  |
| `make backup`         | Сохраняет дамп PostgreSQL в `.local/backups/`              |
| `make logs`           | Показывает логи сервисов                                   |
| `make down`           | Останавливает стек, не удаляя тома                         |

Для `make check` сначала нужен `make install`. Для `make integration` — работающий PostgreSQL и `.env`. Для `make smoke` — весь стек с двумя локальными демопользователями; npm-зависимости самому скрипту не нужны.

CI начнёт работать, когда содержимое шаблона станет корнем отдельного репозитория. Внутри текущей папки `.github/workflows/ci.yml` ничего не запускает. Деплой и публикация в CI не настроены.

## API

Контракт находится в [packages/contracts/openapi.yaml](packages/contracts/openapi.yaml), общие типы и схема формы — в `packages/contracts/src/index.ts`. Их нужно менять вместе с обработчиками Go. Автоматической генерации типов из OpenAPI пока нет.

| Метод  | Путь                              | Назначение                          |
| ------ | --------------------------------- | ----------------------------------- |
| GET    | `/healthz`                        | Процесс API работает                |
| GET    | `/readyz`                         | PostgreSQL, Redis и S3 доступны     |
| GET    | `/api/v1/me`                      | Текущий пользователь                |
| GET    | `/api/v1/admin/ping`              | Пример доступа с ролью `admin`      |
| GET    | `/api/v1/tasks?limit=20&offset=0` | Список своих задач                  |
| POST   | `/api/v1/tasks`                   | Создание: `{ "title": "Название" }` |
| PATCH  | `/api/v1/tasks/{id}`              | Изменение: `{ "completed": true }`  |
| DELETE | `/api/v1/tasks/{id}`              | Удаление своей задачи               |
| POST   | `/api/v1/files`                   | Загрузка multipart-поля `file`      |
| GET    | `/api/v1/files/{id}`              | Скачивание своего файла             |
| DELETE | `/api/v1/files/{id}`              | Удаление своего файла               |

Браузер обращается к `/api/v1/*` на своём домене. Next.js подставляет Bearer-токен и передаёт запрос в Go. Изменяющие запросы BFF требуют совпадения заголовка `Origin` с `APP_ORIGIN`.

Ошибки имеют вид:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Название должно содержать от 1 до 200 символов",
    "request_id": "идентификатор запроса"
  }
}
```

`X-Request-ID` присутствует во всех ответах Go API; поле `request_id` в теле ошибки может отсутствовать. Пагинация: `items`, `total`, `limit`, `offset`; `limit` от 1 до 100, `offset` от 0 до 100000.

## Начать новый проект

Можно скопировать папку вручную или выгрузить чистый шаблон:

```sh
node scripts/export.mjs /путь/к/новому-проекту имя-проекта
```

Скрипт создаёт новый каталог, исключает зависимости, сборки, секреты, локальные данные и историю Git. Существующий каталог не перезаписывает. Репозиторий не создаёт и ничего не отправляет в сеть. После экспорта:

```sh
cd /путь/к/новому-проекту
make up
```

Название в `package.json`, lockfile, стартовой странице, metadata, Keycloak и Compose будет заменено. Имена пакетов `@starter/*`, realm `hackathon` и Go-модуля останутся стабильными; это позволяет начать работу без массового переименования импортов.

Следующие шаги:

1. Уточнить один основной сценарий и распределить работу команды — [docs/hackathon-start.md](docs/hackathon-start.md).
2. Поменять страницу в `apps/web/src/screens/dashboard`, тему в `packages/ui/src/styles.css`.
3. Заменить модуль `tasks` своей предметной областью по [docs/development.md](docs/development.md).
4. Настроить внешний домен, OIDC и сервер по [docs/deployment.md](docs/deployment.md).

## Если что-то не запускается

- `Cannot connect to the Docker daemon`: запустите Docker Desktop.
- Порт занят: остановите другую копию или согласованно поменяйте порты и адреса в Compose, `.env`, `apps/web/.env.local` и redirect URI Keycloak.
- `Invalid redirect_uri`: проверьте `APP_ORIGIN` и клиент `hackathon-web` в realm `hackathon`. Повторный импорт не обновляет существующий realm.
- Пароль не подходит после изменения `.env`: пользователь уже сохранён в Keycloak. Поменяйте пароль через админку или верните прежнее значение в `.env`.
- Ошибка audience: проверьте mapper `api-audience`; access token должен содержать `hackathon-api` в `aud`.
- API не готов: `docker compose --profile app logs api migrate postgres redis s3 keycloak`.
- После перезапуска Next.js нет входа: войдите снова. Если адрес не менялся, сначала проверьте cookies и время на компьютере.

Удаление томов не входит в обычную остановку. Перед удалением данных сделайте резервную копию; `make setup` не сбрасывает существующую базу.

Результаты последней проверки шаблона: [docs/verification.md](docs/verification.md).
